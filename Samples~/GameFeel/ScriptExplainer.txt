PURPOSE:
A single MonoBehaviour that adds five independent visual feedback effects
(hitpause, squash & stretch, afterimage, screen flash, ghost trail) to any
GameObject through EventBus triggers. These micro-feedback effects are the
difference between a prototype and a polished game — the 2-frame hitpause
when a sword connects, the squash on landing, the white flash on damage.

Every effect is independently toggleable, has zero runtime cost when disabled,
and requires no modifications to existing mechanics.

SCRIPT: EventBus.cs
NAMESPACE: GameplayMechanicsUMFOSS.Core
----------------------------------------------------

Code    : public static class EventBus
Explain : A static class so it can be accessed from anywhere without instantiation.
          Acts as a central message broker — publishers and subscribers never
          reference each other directly.

Code    : private static readonly Dictionary<Type, List<Delegate>> subscribers
Explain : Maps each event type (like OnDamageTaken) to a list of callback delegates.
          Using Type as the key means we get O(1) lookup per event type, not O(n)
          linear scanning through all subscribers.

Code    : public static void Subscribe<T>(Action<T> callback)
Explain : Registers a callback for event type T. Generic type parameter ensures
          compile-time safety — you cannot accidentally subscribe a damage handler
          to a jump event.

Code    : public static void Publish<T>(T eventData)
Explain : Notifies all subscribers of type T. Creates a copy of the subscriber list
          before iterating so that callbacks can safely unsubscribe during invocation
          without causing a collection-modified exception.

Code    : public static void Clear()
Explain : Removes all subscribers. Called during scene transitions to prevent
          stale references from destroyed GameObjects receiving events.

SCRIPT: GameFeelEvents.cs
NAMESPACE: GameplayMechanicsUMFOSS.Systems
----------------------------------------------------

Code    : public struct OnHitRegistered
Explain : Structs (not classes) are used for events because they are allocated on the
          stack, not the heap. This means publishing events generates zero garbage
          collection pressure — critical for a system that fires dozens of events
          per second during gameplay.

Code    : public Vector3 hitPoint; public float intensity;
Explain : Payload fields let subscribers react contextually. A screen flash might
          use intensity to scale its alpha. A particle system might spawn at hitPoint.
          The publisher does not need to know what subscribers will do with the data.

SCRIPT: ObjectPoolManager_UMFOSS.cs
NAMESPACE: GameplayMechanicsUMFOSS.Utils
----------------------------------------------------

Code    : private readonly Queue<GameObject> availableObjects
Explain : A Queue (FIFO) is used instead of a List because Dequeue/Enqueue are O(1)
          operations. For a pool that rapidly gets and returns objects, this avoids
          the O(n) cost of List.RemoveAt(0).

Code    : private void PreWarm()
Explain : Front-loads all Instantiate calls to Awake, before gameplay begins.
          This eliminates frame spikes from runtime instantiation. In the Profiler,
          you should see zero Instantiate calls after the first frame.

Code    : public GameObject Get(Vector3 position, Quaternion rotation)
Explain : Returns a pre-existing inactive object instead of calling Instantiate.
          If the pool is exhausted (all objects in use), it creates one more as a
          fallback — the pool grows but never shrinks, avoiding repeated allocation
          in edge cases.

Code    : public void Return(GameObject obj)
Explain : Instead of Destroy, deactivates and re-enqueues. This is the core of
          pooling: the same 10 objects can serve thousands of afterimage spawns
          over an entire play session.

Code    : public void Initialize(GameObject poolPrefab, int size)
Explain : Allows runtime configuration — GameFeel_UMFOSS creates the afterimage
          prefab programmatically and passes it here, so the pool does not require
          any manual Inspector setup.

MAIN SCRIPT: GameFeel_UMFOSS.cs

----------------------------------------------------
SECTION: SERIALIZED FIELDS — HITPAUSE
----------------------------------------------------

Code    : [SerializeField, Range(0.01f, 0.2f)] private float hitpauseDuration = 0.05f;
Explain : The sweet spot for hitpause is 0.02–0.08 seconds (1–4 frames at 60fps).
          Anything shorter is imperceptible; anything longer feels like lag.
          Range attribute clamps the slider in the Inspector to prevent designers
          from setting values that break game feel.

Code    : [SerializeField, Range(0f, 0.1f)] private float hitpauseTimeScale = 0f;
Explain : 0 means full freeze (Time.timeScale = 0). 0.1 means near-freeze where
          physics and animations crawl in slow motion. Full freeze is punchier;
          near-freeze preserves animation continuity.

----------------------------------------------------
SECTION: SERIALIZED FIELDS — SQUASH & STRETCH
----------------------------------------------------

Code    : private Vector3 jumpStretchScale = new Vector3(0.8f, 1.3f, 1f);
Explain : On jump, the character compresses horizontally (0.8) and elongates
          vertically (1.3). This is physically wrong — real objects do not stretch
          when jumping — but perceptually it communicates upward force. Animation
          principle borrowed from Disney's 12 principles of animation.

Code    : private AnimationCurve squashRecoveryCurve
Explain : The curve's Y-axis controls the interpolation factor over time.
          The default curve peaks at 1.15 before settling at 1.0, producing
          a springy overshoot. Designers can edit this in the Inspector to tune
          the bounciness without touching code.

----------------------------------------------------
SECTION: SERIALIZED FIELDS — AFTERIMAGE
----------------------------------------------------

Code    : private Color afterimageStartColor = new Color(0.5f, 0.8f, 1f, 0.6f);
Explain : Semi-transparent blue tint. The alpha of 0.6 means the afterimage starts
          at 60% opacity and fades to 0%. The color tint distinguishes afterimages
          from the real character — without it, players see confusing duplicates.

Code    : [SerializeField, Range(1, 30)] private int afterimagePoolSize = 10;
Explain : Controls how many afterimage sprites exist in the pool. At a spawn interval
          of 0.05s and a lifetime of 0.4s, a maximum of 8 afterimages will be alive
          simultaneously (0.4 / 0.05 = 8). Setting pool size to 10 adds a safety
          margin without wasting memory.

----------------------------------------------------
SECTION: SERIALIZED FIELDS — SCREEN FLASH
----------------------------------------------------

Code    : private AnimationCurve flashCurve
Explain : Sharp spike at t=0 (value 1.0) decaying to 0 at t=1.0 reads as impact.
          A slow ramp would read as a transition or fade. The curve shape is the
          primary tool for controlling whether a flash feels like a hit, a heal,
          or a scene change.

----------------------------------------------------
SECTION: UNITY LIFECYCLE — Awake
----------------------------------------------------

Code    : CacheOriginalScale();
Explain : Stores the transform's localScale at Awake so squash/stretch recovery
          always returns to the correct scale. Critical for non-uniform base scales
          like (2, 1, 1) — recovering to hardcoded (1,1,1) would shrink the object.

Code    : CreateScreenFlashCanvas();
Explain : Auto-creates a ScreenSpaceOverlay Canvas with a full-screen Image at
          sort order 999. This removes the most common friction point — developers
          skip game feel systems that require manual Canvas/Image setup. The canvas
          is configured with raycastTarget = false so it never intercepts gameplay clicks.

Code    : CreateAfterimagePool();
Explain : Builds a minimal SpriteRenderer prefab at runtime, then initializes the
          ObjectPoolManager_UMFOSS with it. Pre-warms the pool so the Profiler shows
          zero Instantiate calls during gameplay.

----------------------------------------------------
SECTION: EVENT HANDLERS
----------------------------------------------------

Code    : private void HandleHitRegistered(OnHitRegistered evt) { TriggerHitpause(); TriggerScreenFlash(flashColorHit); }
Explain : Each EventBus callback maps to one or more effect triggers. This is the
          event subscription map from the issue — OnHitRegistered fires hitpause AND
          screen flash. The handler is lightweight: it delegates to the actual effect
          methods, keeping the mapping readable at a glance.

----------------------------------------------------
SECTION: HITPAUSE HANDLER — THE KEY INSIGHT
----------------------------------------------------

Code    : yield return new WaitForSecondsRealtime(hitpauseDuration);
Explain : THIS IS THE MOST IMPORTANT LINE IN THE ENTIRE SCRIPT.
          When Time.timeScale is set to 0, WaitForSeconds waits INDEFINITELY because
          it measures scaled time (which is frozen). WaitForSecondsRealtime measures
          wall-clock time, completely unaffected by timeScale. Without this, the game
          would freeze permanently on the first hitpause. This is the single most
          common hitpause bug in Unity — almost every implementation you find online
          that uses WaitForSeconds is broken.

Code    : float previousTimeScale = Time.timeScale;
Explain : Saves the current timeScale before overriding it. This handles the edge case
          where hitpause triggers during an existing slow-motion effect — after the
          pause, timeScale restores to the slow-motion value, not to 1.0.

Code    : private void RestoreTimeScale()
Explain : Safety net in OnDisable. If the component is disabled or the GameObject is
          destroyed mid-pause, timeScale would remain at 0 permanently. This guard
          ensures the game never gets stuck in a frozen state.

----------------------------------------------------
SECTION: SQUASH & STRETCH — LerpUnclamped EXPLAINED
----------------------------------------------------

Code    : target.localScale = Vector3.LerpUnclamped(deformedScale, originalScale, curveValue);
Explain : Vector3.Lerp clamps the interpolation factor t between 0 and 1. This means
          even if the AnimationCurve outputs 1.15, Lerp treats it as 1.0 — no overshoot.
          LerpUnclamped does NOT clamp t. When curveValue is 1.15, the scale momentarily
          exceeds originalScale before settling back. This overshoot creates the springy,
          alive feeling that makes squash/stretch look organic instead of mechanical.

          Without LerpUnclamped: deform → linear return → stop. Feels robotic.
          With LerpUnclamped: deform → overshoot → settle. Feels alive.

Code    : float duration = 1f / squashRecoverySpeed;
Explain : Recovery speed of 12 means the full recovery takes 1/12 ≈ 0.083 seconds.
          Inverting the speed to get duration keeps the Inspector intuitive — higher
          number = faster recovery, which matches what designers expect.

----------------------------------------------------
SECTION: AFTERIMAGE HANDLER
----------------------------------------------------

Code    : if (!afterimageEnabled || !isAfterimageActive || sourceSprite == null) return;
Explain : Triple guard at the top of UpdateAfterimage. When ANY condition is false,
          the entire method is a single boolean check — no allocations, no lookups,
          no component queries. This is what "zero cost when disabled" means in practice.

Code    : ghostRenderer.sprite = sourceSprite.sprite;
Explain : Copies the current sprite (including animation frame) from the source.
          This means afterimages capture the exact pose at the moment of spawning,
          creating a motion trail that reads as speed.

Code    : StartCoroutine(FadeAndReturnAfterimage(ghost, ghostRenderer));
Explain : Each afterimage manages its own fade lifecycle. When the fade completes,
          the afterimage returns itself to the pool via afterimagePool.Return(ghost).
          The coroutine is lightweight — just a color lerp per frame for lifetime seconds.

----------------------------------------------------
SECTION: SCREEN FLASH HANDLER
----------------------------------------------------

Code    : elapsed += Time.unscaledDeltaTime;
Explain : Uses unscaledDeltaTime instead of deltaTime so the flash still plays during
          hitpause (when timeScale is 0). Without this, a hitpause + flash triggered
          simultaneously would freeze the flash mid-animation.

----------------------------------------------------
SECTION: GHOST TRAIL HANDLER
----------------------------------------------------

Code    : float velocity = (transform.position - previousPosition).magnitude / Time.deltaTime;
Explain : Calculates velocity from position delta rather than reading from a Rigidbody.
          This makes the ghost trail work on ANY moving object — kinematic bodies, animated
          transforms, tweened objects — not just physics-driven entities.

Code    : bool shouldBeActive = isDashGhostTrailActive || velocity > ghostTrailSpeedThreshold;
Explain : Two activation paths: forced on during a dash (via EventBus), or automatically
          enabled when velocity exceeds the threshold. The OR condition means dashing
          always shows the trail even at low speeds, while fast movement shows it
          regardless of dash state.

Code    : public void SetAllEffectsEnabled(bool enabled)
Explain : Master toggle for the demo scene UI. Sets all five booleans in one call.
          The demo scene uses this for the ALL ON / ALL OFF toggle that demonstrates
