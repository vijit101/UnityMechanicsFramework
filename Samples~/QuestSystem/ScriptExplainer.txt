====================================================
MECHANIC: Quest / Objective System (UMFOSS)
NAMESPACE: GameplayMechanicsUMFOSS.Systems
SAMPLE: GameplayMechanicsUMFOSS.Samples.QuestSystem
CORE: GameplayMechanicsUMFOSS.Core (EventBus, GameEventPayload, ISaveable_UMFOSS)
====================================================

PURPOSE
-------
Designers define quests and objectives as ScriptableObjects. Gameplay code never references
the quest system: it only publishes typed gameplay events and a parallel GameEventPayload
bridge. QuestManager_UMFOSS listens ONLY to GameEventPayload, matches string eventType and
optional property filters, and advances counters. This keeps the quest assembly free of
imports like EnemyDiedEvent from combat.

WHY GameEventPayload
----------------------------------------------------
If QuestManager subscribed to EnemyDiedEvent directly, the quest system would depend on
combat assemblies and would need recompilation when adding FishCaughtEvent. Instead,
gameplay publishes:
  EventBus.Publish(new GameEventPayload(...));    // for quests
The quest manager code never imports EnemyDiedEvent.

----------------------------------------------------
WHY objectiveListeners DICTIONARY
----------------------------------------------------
Key = objective.data.eventTypeKey (e.g. "EnemyDiedEvent"). Value = set of active quest
instances that have at least one objective listening to that key. When a payload arrives,
only those quests are considered — not every objective in the game.

----------------------------------------------------
WHY ScriptableObjects
----------------------------------------------------
New quests are authoring-only: duplicate assets, edit fields, assign objectives. No C#
changes, no rebuild for content-only iteration. The sample also builds SOs in code to keep
the demo self-contained without authored assets.

----------------------------------------------------
ISaveable_UMFOSS
----------------------------------------------------
CaptureState returns QuestSaveData_UMFOSS with active objective counters and completed IDs.
RestoreState rebuilds instances from questID strings using RegisterQuestData / Resources
and re-registers payload listeners. The sample layers world state (consumed pickups/enemies,
player position) on top via QuestSampleFullSave.
